## How LT Represented Logic

How could a program find the right-hand part of a formula? In the paper's account, the logic language (LL) provided memories and information processes; the logic theorist (LT) was a particular program using them, with rules for when processes occurred. Finding a part required both a way to describe its place in an expression and a way to retrieve it from memory.

The paper's expression 1.7 is “-p .→. q v -p,” read as “not-p implies (q or not-p).” Here we write it as **¬p → (q ∨ ¬p)**: the negation and disjunction signs are changed, and parentheses replace the paper's punctuation dots. The expression has a tree structure. Its main element is →; to the left is ¬p, and to the right is ∨, with q and ¬p beneath it. Each element has an associated subexpression: the element ∨, for example, heads the right-hand subexpression q ∨ ¬p.

The paper represents variables and connectives as elements, but does not make a separate element for a negation sign. Instead, symbols associated with an element record its properties. One symbol, G, records negation: each of the two p elements in this expression has G = 1. They share the variable name p, yet occupy distinct places in the tree.

Those places have paths. The main element has position “none”: no left or right branch is needed to reach it. The left p has position L; the ∨ has R; q has RL; and the other p has RR. Each letter records a branch taken from the main element. The position symbol **P** describes that path; **A** identifies the storage location of the whole expression, not the address of an individual element.

The tree is not the order in which the elements must be stored. The paper says the order in a storage list is arbitrary and gives a possible list for this expression: q at RL, ¬p at L, ∨ at R, → at none, and ¬p at RR. The position held with each element preserves its place in the tree, while list order can be used to search for it. A working memory, by contrast, holds a single element, alongside additional descriptive spaces.

Now suppose working memory x holds the main element of X(1.7), including its whole-expression location A(1.7) and its position, none. This is a teaching instantiation of the paper's general operation, not an execution it reports. The instruction **FR x y** finds the right subelement of the element in x and puts it in working memory y. Starting at the root, append R to the empty path: the desired position is R. Using A(1.7), search the possible storage list in order. The first two entries have positions RL and L; the third has P = R, so transfer its ∨ element to y. The operation locates a part of the expression; it does not by itself prove the expression.

This retrieval is one information process, not a complete proof strategy. The paper distinguishes an operation's processing component, which changes memory content, from its control component, which transfers control. A list of instructions with a control network is a routine; only routines meeting the language's stated restrictions can define new information processes. Finding and transferring an element makes that piece available for further processing. What sequence of processes will find a proof is a further question.
