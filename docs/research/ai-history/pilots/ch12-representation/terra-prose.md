## How LT Represented Logic

How could a program find the element heading the right-hand part of a formula? In the paper's model, information to be processed must be brought from storage into working memory and then returned. Finding the element requires both a way to describe its place in an expression and a way to retrieve it.

The paper's expression 1.7 is “-p .→. q v -p,” read as “not-p implies (q or not-p).” It calls the whole expression X(1.7). Here we write it as **¬p → (q ∨ ¬p)**: the negation and disjunction signs are changed, and parentheses replace the paper's punctuation dots. The paper also draws it as a tree. Its main element is →; to the left is ¬p, and to the right is ∨, with q and ¬p beneath it. Each element has an associated subexpression: the element ∨, for example, heads the right-hand subexpression q ∨ ¬p.

The paper represents variables and connectives as elements, but does not make a separate element for a negation sign. Instead, symbols associated with an element record its properties. One symbol, G, counts negation signs before an element's expression: each of the two p elements has G = 1. They share the variable name p, yet occupy distinct places in the tree.

Those places have paths. The main element has position “none”: no left or right branch is needed to reach it. The left p has position L; the ∨ has R; q has RL; and the other p has RR. Each letter records one left or right step on the way down from the main element. The position symbol **P** describes that path; **A** identifies the storage location of the whole expression, not the address of an individual element. For X(1.7), that location is A(1.7).

Storage need not follow the tree. The paper says the order in a storage list is arbitrary and gives a possible list for this expression: q at RL, ¬p at L, ∨ at R, → at none, and ¬p at RR. Each element's information locates it in the tree; list order is used only for searching. A working memory, by contrast, holds a single element, alongside additional descriptive spaces. Three specially located lists hold main elements: T for axioms and proved theorems, P for active problems, and Q for inactive problems. The list name P is distinct from the position symbol P.

Suppose, as an illustration rather than an execution the paper reports, that working memory x holds the main element of X(1.7), including its whole-expression location A(1.7) and its position, none. The instruction **FR x y** finds the right subelement of the element in x and puts it in working memory y. Starting at the root, append R to the empty path: the desired position is R. Using A(1.7), search the possible storage list in order. The first two entries have positions RL and L; the third has P = R, so transfer its ∨ element to y. Now y holds only that ∨ element, with P = R and A(1.7), not the whole subexpression q ∨ ¬p. Reaching its child elements requires further operations.

This retrieval is one information process. The paper distinguishes an operation's processing component, which changes memory content, from its control component, which transfers control. A list of instructions with a control network is a routine; only routines meeting the language's stated restrictions can define new information processes. Finding and transferring an element makes it available for further processing. What sequence of processes will find a proof is a further question.
