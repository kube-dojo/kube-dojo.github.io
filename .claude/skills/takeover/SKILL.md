# Takeover

- Read the original task, linked issue or PR, subsequent instructions, reviews and unresolved findings; treat handoffs as leads to verify, not proof. Establish the original scope and authority to continue.
- Check live ownership, branch and PR heads, worktrees, unpushed work and applicable pipeline leases before acting. Do not duplicate a healthy active lane or overwrite a moving source; report ownership conflicts and inseparable unrelated work.
- Preserve verified Git authorship, co-author trailers, links to the original work, and review findings and budget. Do not guess contributor identities or erase evidence; avoid destructive cleanup.
- Recheck the original problem, current base and relevant behavior, then continue within the authorized scope and repository worktree rules. Recheck the source head before pushing; reassess if it moved.
- Hand the inherited state, exact head, credit, findings and verification limits to [full-send](../full-send/SKILL.md) to deliver the original goal; use [full-stop](../full-stop/SKILL.md) only when the brief explicitly requires a ready-to-merge handoff.
